# 项目状态与验收边界

版本：**0.1.0**（2026-10-30）

这份表回答“现在能信什么”，不替代部署记录。原则是：代码存在、单元测试通过、真实部署验证是三个不同层次；没有对应证据的能力不标“稳定”。

## 状态定义

| 状态 | 含义 |
|---|---|
| 稳定 | 有离线测试，且关键路径做过真实部署或浏览器验证；可以作为默认能力使用 |
| 实验 | 功能可用，但依赖特定模型/供应商/平台，或只在小范围验证过；默认不作为承诺 |
| 未验收 | 代码或设计存在，但当前版本缺少完整验收证据；不要据此对外承诺 |
| 未启用 | 代码保留，配置默认关闭；开启前需要重新验收 |

## 证据原则

- 单元测试通过不等于真实模型、真实 MinIO、真实浏览器或真实 VPS 通过。
- 旧版本的容量/可用性报告只对应旧版本，不能自动继承。
- 失败安全（报错、不扣次、不回退 host）本身是验收项，不以“功能可用”替代。
- 公开仓库只保留可公开的代码、测试和状态；部署密钥、业务数据和完整验收记录不进入仓库。
